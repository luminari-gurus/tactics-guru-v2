# Proposal

## Why

Issue [#316](https://github.com/luminari-gurus/tactics-guru-v2/issues/316) records a
Mage acceptance journey coupled to hand-picked dungeon seed 68 after movement
changes invalidated seed 46. Focused ability/save proof should remain useful
without replaying a fortunate multi-encounter progression path.

## What Changes

- Share one bounded, deterministic pure-helper selection between unit and
  browser progression witnesses, with explicit qualification and failure.
- Add the missing focused production saved-battle Mage integration using
  honestly staged valid state and existing HUD/save paths.
- Retain every complete earned-progression/replay/reload/terminal assertion,
  six engine/device profiles and existing per-case deadlines.
- Record current-source timing, candidate outcomes and acceptance mapping.

## Capabilities

### New Capabilities

None. This change refactors verification; it adds no product capability.

### Modified Capabilities

None. Existing combat, progression and persistence requirements are unchanged.
`skip_specs: true` records that distinction; no artificial delta spec is needed.

## Impact

Tests/helpers, affected units and production browser cases, one task-scoped
self-hosted qualification workflow, portable QA evidence and the approved
[plan](../../../docs/ongoing-projects/issue-316-mage-acceptance-fixtures-plan.md). No runtime, dependency, save,
balance or test-budget changes. Branch: `branch/issue-316-mage-acceptance-fixtures`;
base: `1a02557`. The caller authorized implementation and OpenSpec on 2026-11-09.
